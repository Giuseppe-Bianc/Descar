# Implementation Plan: Semantic Type Checking

**Branch**: `001-type-checking` | **Date**: 2026-09-15 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-type-checking/spec.md` and architectural prompt constraints.

---

## Summary

Add a multi-pass semantic type-checking subsystem to `descar-core` that executes between parsing and code generation. The system is organized strictly by **compilation phase** (`binder`, `resolve`, `sig`, `check`, `globals`, and cross-cutting `diag`), with each phase exposing a dedicated public entry point, distinct error types, and receiving a linearly threaded `&mut CheckerCtx`. It validates variable declarations, local type inference, operator operands, function signatures, return types, and control-flow conditions while detecting infinite-size recursive types and scoping errors. Diagnostics are attributed with originating phase metadata, mapped to `CompileError::TypeError`, and safeguarded against regression via `insta` snapshot testing.

---

## Technical Context

**Language/Version**: Rust 1.98.1, Edition 2024, stable channel pinned via `rust-toolchain.toml` with `channel = "1.98.1"`. Toolchain updates are performed manually via dedicated review PRs, never automatically in CI.

**Primary Dependencies**:

- Core (`descar-core`): Rust Standard Library (`std`) only (`std::collections::HashMap`, `Vec`). No external dependencies in production. No string-interning crates until profiling justifies them. Manual `Display` implementation for error types (<40 LOC per module) avoiding `thiserror` in new modules.
- Testing (`dev-dependencies`): `insta = "1.48.0"` for diagnostic snapshot tests.

**Storage**: In-memory only for the duration of a single compiler invocation (`SymbolTable`, `TypeTable`, `Vec<Diagnostic>`). Incremental query engines (e.g. `salsa`) are out of scope until LSP requirements emerge.

**Testing**:

- Unit testing with hand-constructed synthetic ASTs for `binder`, `resolve`, and `sig` (isolated from `JsavParser`).
- Integration snapshot testing with `insta` for sample source files in `tests/fixtures/`.
- Interactive snapshot diff management via `cargo insta review`.

**Target Platform**: Cross-platform (Linux, macOS, Windows).

**Project Type**: Compiler library (`descar-core`) integrated with CLI driver (`descar`).

**Performance Goals**: Type checking adds $\le 15\%$ overhead to compilation time on average for 1k–10k LOC (SC-003).

**Constraints**:

- Single sequential context `CheckerCtx` passed as `&mut CheckerCtx` avoiding `Rc<RefCell<_>>`.
- Zero implicit type coercion across primitives (FR-011).
- Multi-pass AST traversal to support forward references within the same scope without flow-sensitive analysis (FR-012).
- Zero compiler warnings (`cargo clippy --all-targets --all-features -- -D warnings`).

**Scale/Scope**: Programs up to 10k LOC; comprehensive coverage of all Descar primitive types, composite types (arrays, vectors), structs, enums, functions, and control flow.

**Structure Decision**: Place all semantic type checker implementation inside `crates/descar-core/src/semantic/`, exposing `descar_core::semantic::check_program`. Update `crates/descar/src/main.rs` to invoke `check_program` in `Command::Check` and `Command::Compile`. Keep core dependencies zero-external; place snapshot tests and fixtures in `crates/descar/tests/`.
